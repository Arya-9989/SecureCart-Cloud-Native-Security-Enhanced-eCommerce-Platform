# 0007. Kubernetes manifests with TLS termination

- Status: accepted
- Date: 2026-10-23

## Context

SecureCart shipped only as a docker compose stack. A production deployment needs:

- TLS termination;
- several replicas with safe rollouts;
- explicit network boundaries between components;
- hardened pods;
- a release step for migrations that does not race between replicas.

The manifests must be checked in CI and actually run somewhere free and local.

## Options considered

- **Helm chart.** Flexible, but templates hide the rendered YAML. A reviewer reads
  `{{ if }}` blocks instead of manifests.
- **Kustomize base plus overlays (chosen).** Plain YAML that kubeconform and Trivy can check
  directly, with environment differences expressed as small patches.
- **Ingress controller for local runs.** ingress-nginx was retired by Kubernetes SIG Network
  in March 2026. Traefik v3 is maintained, supports the standard `Ingress` API, and is
  already used elsewhere in this portfolio. The manifests use `Ingress`
  (`ingressClassName: traefik`), so any controller works.
- **Certificates.** cert-manager in production; for kind, either a self-signed cert-manager
  issuer or a certificate made by the bring-up script. The script is chosen for kind: it
  avoids installing cert-manager's CRDs and webhooks on a laptop, and the production
  overlay still exercises the cert-manager path in validation.

## Decision

- **`deploy/k8s/base`: the application only.**
  - Backend and frontend Deployments (2 replicas each), each with a Service and a
    PodDisruptionBudget (`minAvailable: 1`) and topology spread.
  - The scheduler Deployment.
  - A `migrate` Job (migrations and the media bucket). The API pods wait for it in an init
    container (`migrate --check`), so no serving pod ever runs migrations.
  - A TLS Ingress, a ConfigMap, a token-less ServiceAccount, and the namespace with the
    `restricted` Pod Security Standard enforced.
- **Every pod is hardened:** non-root numeric UID, `readOnlyRootFilesystem`, no privilege
  escalation, all capabilities dropped, `RuntimeDefault` seccomp, no service-account
  token, no service-link env vars, memory-backed `emptyDir` for `/tmp`, and resource
  requests and limits on every container. The backend image now declares a numeric
  `USER 10001:10001`, so `runAsNonRoot` can be verified.
- **Probes.** The backend has a startup probe, a readiness probe on `/api/health/` (with
  `Host: backend`, which is in `ALLOWED_HOSTS`) and a TCP liveness probe: a database outage
  removes pods from rotation instead of restarting them in a loop. The frontend is probed
  on `/healthz`; the scheduler on its heartbeat file. `preStop` delays let endpoints drain.
- **NetworkPolicies: deny everything, then allow each path the application uses:**
  - DNS for every pod;
  - the ingress controller's namespace to the frontend on 8080;
  - the frontend to the backend on 8000;
  - backend, scheduler and the Jobs to data-service pods on 5432, 6379, 9000 and 1025;
  - in kind, the data services accept only those clients;
  - in production, egress to managed services on their ports only, never to private
    ranges or `169.254.0.0/16` (cloud metadata).
- **TLS.** The base Ingress terminates TLS with the `securecart-tls` Secret.
  - `overlays/production` adds `cert-manager.io/cluster-issuer: letsencrypt-production`
    and a `ClusterIssuer` (ACME HTTP-01 through Traefik), so cert-manager issues and renews
    the certificate.
  - `overlays/kind` uses a certificate generated by `deploy/k8s/scripts/kind-up.sh`, and the
    smoke test verifies HTTPS against that certificate, not with `--insecure`.
  - HTTP redirects to HTTPS at Traefik. Django trusts `X-Forwarded-Proto` and counts two
    proxy hops (ingress, then nginx) for client IPs.
- **`overlays/kind`** adds in-cluster PostgreSQL (StatefulSet with a PVC), Redis, MinIO and
  Mailpit (all hardened the same way), a seed Job, and random secrets generated into a
  git-ignored `secrets.env`.
- **CI** renders both overlays with checksum-verified kustomize, validates them with
  `kubeconform -strict` against Kubernetes 1.37 (cert-manager schemas from a pinned commit
  of the datreeio CRD catalog), and fails on HIGH or CRITICAL `trivy config` findings.

## Consequences

- kind's default CNI (kindnet) does not enforce NetworkPolicies. The kind run proves the
  manifests deploy and serve, not that the policies block traffic; that needs a policy-aware
  CNI such as Calico or Cilium. The policies are validated by schema and reviewed by Trivy.
- The migrate Job is immutable once created: a new release deletes it before applying (the
  script does). In a CD system this is a pre-deploy hook.
- `overlays/production` uses placeholder hosts, emails and image tags, and expects the
  Secret to be provisioned out of band (External Secrets, Sealed Secrets). Nothing
  secret is committed.
